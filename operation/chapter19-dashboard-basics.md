# 第十九章 控制台基础操作

## 本章目标

通过本章，读者将掌握壬远 AI 网关（Rainway AI Gateway）Dashboard 的访问方式、界面组织与基础操作流程，理解控制台背后的核心概念（模型服务商、AI 业务集群、Entity、API Key、路由表等），并能够独立完成首次配置。具体包括：

- 如何登录 Dashboard 并修改默认账号；
- 控制台各导航入口的职责与数据对应关系；
- 用户、角色（系统管理员 / 只读）、Token 与权限 Scope 的管理方式；
- 只读角色的界面差异与敏感字段脱敏规则；
- 控制台通用交互约定（抽屉表单、视图 / 编辑双模式、通知）；
- 批量任务与密钥收敛两个运维页面的结构与操作要点；
- 配置版本跟踪机制；
- 数据报表（总览 + 明细页签）与操作日志（写操作审计）的查询方式；
- 部署后通过 `branding/` 定制控制台标题与图标；
- 从实例池登记到第一次 curl 调用成功的完整首次配置流程。

## Dashboard 访问方式与默认账号

Dashboard 是壬远 AI 网关的管理控制台（Admin Console），它以 Web UI 形式调用 AI Gateway API 的 OpenAPI v1 接口，完成策略与配置的可视化管理。在本地或测试环境启动 AI Gateway API 后，默认可通过浏览器访问登录页：

```
http://api-server:8183/login
```

直接访问 `http://api-server:8183/` 未登录时也会重定向到登录页。其中 `8183` 为 AI Gateway API 的服务端口（ServerPort），可在 `conf/ai_gateway_api.toml` 的 `[Server]` 段落中修改；监控端口（MonitorPort）默认为 `8284`，用于暴露指标与健康检查，不直接提供控制台界面。

首次登录时，系统预置管理员账号：

| 项目 | 默认值 |
|------|--------|
| 用户名 | `admin` |
| 密码 | `admin` |

登录成功后，Dashboard 会保存由 `/auth/session-keys` 生成的 session key，并在后续请求中以 `Authorization: Session {session_key}` 的方式携带鉴权信息。生产环境中应在首次登录后立即修改默认密码，并为不同运维人员创建独立账号。

### 品牌定制（部署后可配置）

控制台侧边栏、登录页、浏览器标签页的标题与 favicon 由静态产出根目录下的 `branding/` 目录控制，部署后直接编辑即可生效，无需重新构建前端：

```
static/
├── index.html
├── static/
└── branding/
    ├── branding.json   // 标题与 favicon 配置
    └── favicon.ico     // 站点图标
```

```json
{
  "title": "壬远 AI网关",
  "titleEn": "Rainway AI Gateway",
  "favicon": "favicon.ico"
}
```

- `title`：中文界面标题，同时作为其他语言未配置时的兜底；
- `titleEn`：英文界面标题，留空时使用 `title`；
- `favicon`：图标路径，相对路径基于 `branding/` 目录，也可填 `/xxx.ico` 或 `http(s)` 地址；指定的图标文件不存在时不显示图标。

修改后刷新页面生效；若浏览器仍显示旧图标，请强制刷新或清理缓存。部署方式与产出获取见 `ai-gateway-web/docs/zh-cn/deploy.md`。

## 控制台界面导览

登录成功后，控制台呈现「左侧导航 + 右侧内容区」的布局。导航由 `/meta` 接口动态返回，对应 `conf/nav_tree.toml` 中定义的导航树。主导航包括资源管理、路由管理、功能增强、消费者管理、系统安全、数据报表、用户管理与操作日志：

```
AI 网关
├─ 资源管理
│   ├─ AI 业务集群       引用服务商，配置转发策略
│   ├─ 模型定价          模型价格维护与费用核算
│   ├─ 模型服务商        实例池、协议、模型与 Keys
│   └─ EPP调度           EPP 实例池与集群调度分配
├─ 路由管理
│   └─ 路由表            Global / Entity / API-Key 路由规则
├─ 功能增强
│   ├─ AI缓存规则        应答缓存开关与缓存键规则
│   ├─ 流量镜像规则      生产请求副本异步发往镜像集群
│   ├─ 意图配置          问题集与置信度门控阈值
│   └─ AI上下文压缩      压缩规则与全局设置
├─ 消费者管理
│   ├─ API Key 管理      调用凭证签发与治理
│   ├─ 批量任务          provider 原生批量任务的列表、详情与取消
│   └─ Entity 管理       类型 / 组织（配额、限流、模型访问控制）
├─ 系统安全
│   └─ 密钥收敛          库内敏感密钥的批量重加密 / 解密
├─ 数据报表              运营数据可视化：总览指标、图表与日志明细
├─ 用户管理              控制台账号与 Token（管理员）
└─ 操作日志              写操作审计查询（管理员）
```

每个导航项对应一组 OpenAPI 资源：

| 导航项 | 对应 OpenAPI 端点 | 主要职责 |
|--------|-------------------|----------|
| 模型服务商 | `/providers` | 维护模型提供方、后端实例池、API-Key 明文与模型协议 |
| AI 业务集群 | `/clusters` | 维护转发集群、LLM 配置、Key 权重与路由策略 |
| 模型定价 | `/model-prices` | 维护模型在不同 Provider 与时段下的价格，支持分段计价（peak 忙时） |
| EPP调度 | `/epp-pool`、`/epp-assignments` | 维护 EPP 实例池及 EPP 模式集群的调度分配 |
| 路由表 | `/global-route-rules`、`/route-tables` 等 | 维护 global / entity / api-key 三级路由规则 |
| AI缓存规则 / 流量镜像规则 / 意图配置 / AI上下文压缩 | `/ai-cache-rules`、`/traffic-mirror-rules`、`/intent-config`、`/ai-context-rules` | 维护应答缓存、流量镜像、意图分类与上下文压缩策略 |
| Entity 管理 | `/entity-types`、`/entities` | 维护组织类型、组织架构、模型黑白名单、配额与限流策略 |
| 批量任务 | `/batches`、`/batch-files/{file_id}` | 查看 provider 原生批量任务、批量文件元数据并取消任务 |
| API Key 管理 | `/api-keys` | 创建、启用/禁用、配额绑定与密钥查看 |
| 密钥收敛 | `/security/reencrypt-sweeps` | 对库内敏感密钥列执行批量重加密 / 解密并查询历史任务 |
| 数据报表 | `/report/overview`、`/report/timeseries`、`/report/rankings`、`/report/distribution`、`/report/logs` | 运营数据可视化查询，界面分总览、明细两个页签（配置 `[Report]` 后可用，未配置时无数据） |
| 用户管理 | `/auth/users`、`/auth/tokens` | 维护控制台用户与机器 Token |
| 操作日志 | `/operation-logs` | 写操作只读审计查询，含变更摘要与请求上下文 |

### 通用交互约定

- **列表页**：搜索区 + 操作按钮 + 表格 + 分页；多数列表支持「20 条/页」切换（模型定价默认 50 条/页，支持 20–1000 条/页；批量任务固定 50 条/页且为游标分页）。
- **抽屉表单**：创建 / 编辑在右侧抽屉完成，底部「提交 / 取消」（向导类为「下一步 / 上一步」）。
- **视图 / 编辑双模式**：路由规则、AI缓存规则、流量镜像规则、意图配置、AI上下文压缩等集合型配置默认处于视图模式，点「进入编辑模式」后可增删改；改完在抽屉里「本地保存」，再点「提交并生效」才下发，提交后自动退出编辑模式，未提交的修改不影响线上流量（详见「功能增强模块的视图 / 编辑双模式」）。
- **通知**：操作结果以右上角通知呈现；错误通知（如「数据重复」）不自动消失，点 × 关闭。

## 控制台中的核心概念

控制台中的诸多操作都围绕以下概念展开：Provider（模型服务商）、Cluster（AI 业务集群）、Entity（组织）、API-Key、路由表、配额计划与限流策略。

这些概念的完整定义、相互关系与设计动机已在 [第五章 壬远AI网关架构与核心概念](../design/chapter05-system-architecture.md#核心概念) 中统一介绍。本节仅说明它们在 Dashboard 中的对应入口：

| 控制台导航项 | 对应概念 | 说明 |
|---|---|---|
| 资源管理 → 模型服务商 | Provider | 维护模型提供方、后端实例池、模型协议与认证密钥 |
| 资源管理 → AI 业务集群 | Cluster | 引用 Provider，配置转发策略、Key 权重与超时 |
| 资源管理 → 模型定价 | Model Price | 维护模型在不同 Provider 与时段（peak 忙时）下的单价，支持分段计价 |
| 消费者管理 → Entity 管理 | Entity | 维护组织架构、配额、限流与模型访问控制 |
| 消费者管理 → API Key 管理 | API-Key | 签发调用凭证并绑定到 Entity |
| 路由管理 → 路由表 | Route Table | 维护 Global / Entity / API-Key 三级路由规则 |

上述概念对应数据面请求处理顺序（鉴权 → 模型权限 → 限流 → 配额 → 路由 → 转发，详见 [第五章 壬远AI网关架构与核心概念](../design/chapter05-system-architecture.md)）中的不同环节：API-Key 与 Entity 承载鉴权、模型访问控制、限流与配额策略，路由表承载路由匹配规则，Provider 与 Cluster 决定最终的转发目标。

理解这些概念是正确使用 Dashboard 的前提，建议在阅读本章前先浏览第五章的“核心概念”节。

## 用户与权限管理

Dashboard 的用户与权限由 `/auth` 接口族管理，相关定义详见 `ai-gateway-api/design-docs/api-define/OpenAPI接口定义/auth.md`。

### 用户（User）

用户是登录 Dashboard 的自然人账号，分为两种角色：`system_admin`（系统管理员，完整管理权限）与 `system_admin_readonly`（系统管理员（只读），可查看全部资源但所有写操作被禁止，敏感密钥字段脱敏展示）。

- **创建用户**：「用户管理 → 用户」页签右上角「添加用户」打开创建抽屉，字段为用户名、密码、确认密码与「角色」单选项（默认选中「系统管理员」）。
- **用户列表**：「角色」列为「系统管理员 / 系统管理员（只读）」，支持按角色筛选；操作列提供「变更角色」「修改密码」「删除」。
- **变更角色**：抽屉中目标用户名只读，角色为单选项，提交调用 `PATCH /open-api/v1/auth/users/{user_name}/role`（请求体 `{"role": "<role>"}`）。
- **内置账号保护**：内置 `admin` 的角色固定为「系统管理员」，变更角色抽屉不显示角色单选项，仅提示「内置账号 admin 角色固定为系统管理员，不可变更」；对其降级请求会被拒绝。

创建用户时的字段约束：

- 用户名最多 64 字符，仅允许字母、数字、点（`.`）、下划线（`_`）、中划线（`-`），不能以点、下划线、中划线开头或结尾；保留名 `admin`、`root`、`system` 不可用（仅创建时约束，不影响内置账号后续改密等按名引用操作）。
- 密码 8–72 字节（按 UTF-8 字节计），不能包含空格，不能与用户名相同或为其逆序。

管理员可通过 Dashboard「用户管理 → 用户」页签完成新增、删除与密码重置。修改自己密码时需要填写原密码，提交成功后自动退出登录；修改他人密码无需原密码。

### 只读视角

以 `system_admin_readonly` 账号登录后进入只读视角。只读角色与系统管理员看到的是**同一棵导航树**（`conf/nav_tree.toml` 中两个角色共享同一份 `allowed_roles` 配置），因此**菜单与页面不做裁剪**，全部页面均可浏览；差异只体现在：

| 差异项 | 表现 |
|---|---|
| 写操作按钮 | 全站隐藏（前端 `v-has` 指令按权限裁剪），包括列表页的「创建 / 添加 / 导入」、操作列的「编辑 / 删除 / 变更角色 / 修改密码」，以及编辑类页面的「进入编辑模式 / 本地保存 / 提交并生效」，页面恒停留在视图模式 |
| 行内与抽屉内写操作 | 隐藏，如 API Key / Entity 的「重置配额」、服务商列表的「分段计价配置」、批量任务列表的「取消」、密钥收敛的「触发任务」 |
| 密钥类字段 | 读取 API Key、服务商服务鉴权 Key、Token 等端点返回的密钥值由后端**脱敏**为掩码（如 `********`），前端原样展示，掩码值不可用于鉴权；系统管理员登录时仍返回明文 |
| 纯只读模块 | 数据报表与操作日志本身没有写操作与编辑模式，两种角色看到的内容完全一致 |
| 保留的只读能力 | 各列表页的「详情 / 查看」入口与只读抽屉，搜索、排序、分页与筛选控件，「管理路由规则」「查询模型价格」等跳转入口 |

写能力的最终防线在后端：即使绕过前端，只读角色对写端点也会被拒绝（403）。

### Session Key 与 Token

- **Session Key**：由 `/auth/session-keys` 根据用户名和密码生成，用于 Dashboard 登录后的请求鉴权，格式为 `Authorization: Session {session_key}`。Session 有过期时间，默认由 `SessionExpireInDay` 控制。
- **Token**：由 `/auth/tokens` 创建，是内部程序访问 API Server（管理面 API 服务，非数据面转发入口）的鉴权凭证。Token 分为三种 Scope，创建抽屉中以单选形式指定，列表与详情以三态展示：
  - **系统管理（System）**：拥有所有资源的完整管理权限；
  - **系统管理只读（SystemReadonly）**：拥有全部资源的只读权限，与只读管理员角色等价，适用于仅需查看与导出的程序化场景；
  - **内部支持（Support）**：仅可导出部分资源的数据，适用于内部运维排查、数据备份等只读场景，不可创建、编辑或删除任何资源。

生产环境中，应为 Dashboard 操作人员创建独立用户，为 Conf Agent 等机器客户端创建 `Support` Scope 的专用 Token，避免使用 `System` Token 直接暴露给数据面。

## 核心模块速查

控制台各模块通过独立的列表页与表单页完成管理。以下是常用模块的入口与职责：

| 模块路径 | 列表页能力 | 关键操作 |
|----------|-----------|---------|
| 资源管理 → 模型服务商 | 查看 Provider 列表与引用关系 | 创建 Provider、维护实例池 / 模型 / Keys |
| 资源管理 → AI 业务集群 | 查看 Cluster 列表及所属服务商 | 创建 Cluster、配置转发策略、Key 权重 |
| 资源管理 → 模型定价 | 查看模型价格列表 | 导入 / 编辑模型价格、维护分段计价（peak 忙时时段）模板 |
| 资源管理 → EPP调度 | 查看 EPP 实例池与集群分配关系 | 维护 EPP 实例池、查看 / 覆写 EPP 模式集群的调度分配 |
| 路由管理 → 路由表 | 查看 Global / Entity / API-Key 三级路由表 | 启用 / 禁用路由表、编辑路由规则 |
| 功能增强 → AI缓存规则 / 流量镜像规则 / 意图配置 / AI上下文压缩 | 视图模式列表 + 编辑模式 | 进入编辑模式增删改、拖拽排序、本地保存后提交并生效 |
| 消费者管理 → Entity 管理 | 查看 Entity 类型与组织树 | 创建类型 / 组织、配置配额 / 限流 / 模型访问控制 |
| 消费者管理 → 批量任务 | 游标分页表格（无新建入口） | 查看详情、取消非终态任务 |
| 消费者管理 → API Key 管理 | 查看 API Key 列表及挂载组织 | 创建 Key、重置配额、查看密钥 |
| 系统安全 → 密钥收敛 | 触发收敛任务、查看运行中任务与历史任务 | 触发重加密 / 解密（含预演）、查看任务详情 |
| 数据报表 | 总览页签：8 项指标卡 + 7 张图表；明细页签：服务端分页日志表格（配置 `[Report]` 后展示，未配置时菜单不出现） | 按时间窗与维度过滤报表 |
| 操作日志 | 按时间范围与条件筛选写操作审计记录 | 查看详情抽屉（变更摘要 before / after） |
| 用户管理 | 查看控制台用户与 Token | 创建用户、创建 Token、变更角色、修改密码 |

路由规则示例（JSON 视图）如下：

```json
{
  "enabled": true,
  "rules": [
    {
      "name": "global-default",
      "cond": "default_t()",
      "targets": [
        {
          "cluster_name": "deepseek-cluster",
          "model": "",
          "weight": 100
        }
      ],
      "fallbacks": []
    }
  ]
}
```

其中 `cond` 为 BFE 条件表达式，`targets` 中同一规则的权重之和必须等于 100，`fallbacks` 用于指定降级目标。路由规则编辑需先进入编辑模式，本地保存后再提交生效。

## 批量任务（消费者管理 → 批量任务）

批量任务页面用于管控经数据面透传创建的 provider 原生批量任务（OpenAI Batch API：`/v1/files` + `/v1/batches`）。控制台只做管控、不做创建：批量任务由调用方携带 API Key 直接向 provider 发起，数据面在透传时执行创建限流与金额预留 / 结算记账，控制台提供列表、详情、取消与批量文件元数据查询。菜单入口为「消费者管理 → 批量任务」，路由 `/batches`，页面为单一列表页，**没有「新建」入口**。

### 筛选与列表

筛选栏从左到右为：任务状态（下拉）、服务商（输入框）、API Key ID（输入框，回车即查询）、创建时间起、创建时间止、「查询」「重置」。所有条件均可选、可组合（AND 关系）。

表格固定 6 列：批量任务ID、状态、请求计数（展示 `request_counts` 的总数 / 完成 / 失败，形如 `100 / 98 / 2`）、结算状态、创建时间、操作（「详情」+「取消」）。

分页为**主键游标分页**：每页固定 50 条（不可切换），底部只提供「首页 / 上一页 / 第 N 页 · 本页 M 条 / 下一页」，没有总条数与跳页；「查询」与「重置」都会回到第一页；末页因恰好取满一页而返回空列表时，页面自动退回上一页；翻页沿用最近一次「查询」时的筛选条件。

### 状态与结算状态

| 状态取值 | 界面文案 | 是否终态 |
|---|---|---|
| `validating` | 校验中 | 否 |
| `queued` | 排队中 | 否 |
| `in_progress` | 进行中 | 否 |
| `finalizing` | 收尾中 | 否 |
| `cancelling` | 取消中 | 否 |
| `completed` | 已完成 | 是 |
| `expired` | 已过期 | 是 |
| `failed` | 已失败 | 是 |
| `cancelled` | 已取消 | 是 |

结算状态三态：`reserved`（已预留）、`settled`（已结算）、`released`（已释放）。终态任务的「取消」按钮置灰不可点。

### 取消任务

对非终态任务点击「取消」触发二次确认（「确认取消批量任务 {batchId}？取消将调用 provider cancel 端点并释放金额预留。」），确认后调用 `POST /batches/{batch_id}/cancel`，并就地更新该行状态与结算状态，不重新拉取整页。取消失败的提示：409 表示任务已终态或正被其它实例处理，刷新列表以服务端状态为准；502 表示控制面到 provider 出网失败（降级部署无出网时该能力不可用，列表与详情不受影响）；404 表示任务不存在或已被清理。

### 详情抽屉

「详情」打开 70% 宽抽屉，内容为 5 个卡片：基本信息（批量任务ID / 服务商 / API Key ID / 产品名称 / Entity ID / 透传端点）、状态与计数（状态 Tag + 请求总数 / 已完成 / 失败 / 估算行数）、用量与记账（输入与输出 token、用量来源、预留金额、结算金额、结算状态、预留结余、同步来源）、文件与时间（输入文件ID / 输出文件ID / 创建时间 / 更新时间 / 终结时间）、批量文件（6 列表格：文件ID / 服务商 / 用途 / 文件名 / 大小 / 创建时间）。抽屉为纯只读，不含任何写操作按钮。

金额字段（`reserve_units` / `settle_units`）是 1e-8 定点整数（单位 RMB），界面原样展示、不做换算；从 Redis 回源、job 尚未落库的任务，结算类字段可能为空并显示 `-`，属正常现象。批量任务的字段与状态口径详见 `ai-gateway-web/docs/zh-cn/13-batch-tasks.md`，批量限流的四维度配置见 [第二十三章 限流策略配置](./chapter23-rate-limit-config.md)。

## 密钥收敛（系统安全 → 密钥收敛）

密钥收敛用于对网关库内的敏感密钥列（服务商服务鉴权 Key 所在 `providers` 表、API Key 所在 `api_keys` 表）执行批量重加密 / 解密，使历史数据向当前加密形态（keyring 的 active 钥）收敛。入口为「系统安全 → 密钥收敛」，路由 `/security`。

页面为单页三卡片结构：

- **触发收敛任务**：三个参数 + 「触发任务」按钮 —— 变换方向 `mode`（`reencrypt` 重加密 / `decrypt` 解密，后者仅用于回滚预案、日常禁止触发）、扫描范围 `scope`（全部 / 仅 providers 表 / 仅 api_keys 表）、预演模式 `dry_run`（开启后只统计"将要重写"的行数，不写库）。
- **当前运行任务**：展示唯一的运行中任务及其进度；存在运行中任务时按 800ms 轮询单个任务，按 `task_id` 就地更新列表行、本卡片与已打开的抽屉，不重置筛选、页码与排序。
- **历史任务**：筛选栏（状态 / 方向 / 范围 / 预演 / 开始时间起止）+ 服务端分页表格（默认 20 条/页，可切 20 / 50 / 100），操作列「详情」打开 60% 宽抽屉。

任务为**集群级单例**：同一时刻只允许一个收敛任务运行，运行中重复触发返回 409，页面提示持有者 `task_id` 并转为直接轮询该任务，**不排队**。任务详情包含任务ID、状态、变换方向、预演模式、扫描范围、触发者、活跃密钥ID、开始 / 结束时间、耗时与按表分组的统计（已扫描 / 已重写 / 已跳过），运行中时统计与耗时显示占位文案而非 0。

该模块属于系统运维 / 安全类功能，需要 `FeatureSecurity`（Scope=System）权限：无读权限时接口返回 402（`Feature Access Deny`），无权限时菜单不出现。字段级说明见 `ai-gateway-web/docs/zh-cn/16-key-reencrypt.md`。

## 功能增强模块的视图 / 编辑双模式

「功能增强」下的四个模块 —— AI缓存规则、流量镜像规则、意图配置、AI上下文压缩 —— 采用统一的交互范式，理解一次即可套用到其余模块：

| 环节 | 表现 |
|---|---|
| 默认状态 | 进入页面为**视图模式**，表格操作列只有「查看」，页头右上角为「进入编辑模式」 |
| 编辑状态 | 页头出现「添加规则」与「提交并生效」/「退出编辑模式」，操作列变为「编辑」「删除」 |
| 两步保存 | 抽屉里的「本地保存」只把改动放进页面内的草稿集合（不影响线上）；点「提交并生效」才一次性整体下发到控制面 |
| 顺序即优先级 | 规则按列表顺序匹配、首条命中生效；编辑模式下可直接**拖拽表格行**调整次序（列表下方有「拖动表格可修改生效次序」提示），表头排序仅影响展示、不改变实际顺序 |
| 新增位置 | 新增规则插入集合头部（优先级最高），已有规则的相对顺序不变 |
| 退出确认 | 有未提交改动时点「退出编辑模式」会弹出「当前有未提交的改动，退出编辑模式将丢弃这些改动，确认退出？」；确认则回滚到进入编辑模式前的快照，取消则留在编辑模式并保留改动 |

路由表的编辑模式在此基础上还提供行内「复制」，用于快速派生一条相似规则。四种集合型配置的字段语义分别见 `ai-gateway-web/docs/zh-cn/08-ai-cache-rules.md`、`09-traffic-mirror-rules.md`、`10-intent-config.md`、`11-ai-context.md`。

## 配置版本跟踪机制

壬远 AI 网关采用基于 MD5 签名与版本号的配置导出机制，详细设计参见 [第十四章 配置导出与版本控制设计](../design/chapter14-config-export-and-version-control.md)。控制面为每类配置主题（Topic）维护当前版本号与签名，例如 `route_rule`、`ai_route`、`mod_api_key_rule` 等：

- **当前版本号**：格式为 `YYYYMMDDHHMMSS`，例如 `20260102120000`；
- **MD5 签名**：对配置内容（版本号置零后）计算得出的签名；
- **最近变更时间**：签名变化即视为一次有效配置变更。

该机制保证：若配置内容未发生变化，Conf Agent 拉取时返回 `Data: null`，避免无意义的热加载；一旦内容变化，控制面会生成新的版本号并返回全量配置，BFE 据此完成热更新。配置版本信息主要通过 InnerAPI 暴露给 Conf Agent 与运维排查工具，Dashboard 当前重点面向资源管理，版本详情可参考控制面日志或 InnerAPI 导出接口。

## 通过 Dashboard 进行首次配置的完整流程

以下是一个从空环境到第一次调用成功的最小配置流程，对应控制台真实导航入口。更详细的字段说明与示例取值可参考 Dashboard 用户手册 `ai-gateway-web/docs/zh-cn/19-scenarios.md`（场景实战）。

### 步骤 1：登录并修改默认密码

使用默认账号 `admin/admin` 登录后，进入「用户管理 → 用户」，将 `admin` 密码修改为强密码，并根据团队需要新建其他管理员账号（可选择「系统管理员」或「系统管理员（只读）」角色）。

### 步骤 2：创建模型服务商

进入「资源管理 → 模型服务商」，点击「创建服务商」：

- 名称：Provider 唯一标识，例如 `demo-provider`；
- 实例池：后端模型服务的 IP / 端口 / 权重（单实例权重填 100），例如 `172.19.1.187:13801`；
- 模型协议：如 `openai`；
- 服务鉴权 Keys：若后端需要鉴权则填写 Key 名称与明文；
- 模型列表：点击「获取」拉取可用模型并选择，例如 `doubao-pro-32k`。

创建成功后，控制面会自动根据实例池生成后端实例池和子集群。

### 步骤 3：创建 AI 业务集群

进入「资源管理 → AI 业务集群」，点击「创建集群」，按向导分步完成：

1. **基础配置**：填写集群名称（如 `demo-cluster`）、协议（如 `https`）、是否启用会话保持；
2. **超时和重传**：通常保持推荐默认值；
3. **被动健康检查**：通常保持默认；
4. **大模型配置**：选择上一步创建的 Provider（如 `demo-provider`），勾选允许转发的模型（如 `doubao-pro-32k`），并按需引用服务商 Key 设置权重；
5. **复查与检查**：核对汇总信息后点「提交」，集群列表出现新集群即表示创建成功。

### 步骤 4：创建 Entity 组织（可选）

如需按组织统一配置配额、限流或模型访问控制，进入「消费者管理 → Entity 管理」：

- 先创建 Entity 类型（如 `team`，级别 3）；
- 再创建 Entity 组织（如 `dev-team`），允许模型保持 `*` 即可，并按需绑定配额计划、限流策略与模型黑白名单。

### 步骤 5：签发 API Key

进入「消费者管理 → API Key 管理」，点击「创建」：

- 描述：API Key 标识（如 `demo 第一个 Key`）；
- 挂载 Entity：选择步骤 4 中创建的 Entity（可选，跳过步骤 4 则留空）；
- 过期时间：可勾选永不过期，或按需指定；
- 允许子网：默认 `*` 不限制；
- 允许模型等按需填写。

创建成功后，列表中该 API Key 的 Key 值以脱敏形式展示（前 8 位 + `****` + 后 4 位），点击 Key 值可查看完整明文并一键复制，请妥善保存。注意同时记录该 Key 的 Key ID（如 `api-key-1`），下一步配置路由时需按 Key ID 找到对应的 apikey 路由表。Key 值创建后不可修改。

### 步骤 6：配置 API-Key 路由规则

进入「路由管理 → 路由表」，找到属主为步骤 5 中 Key ID 的 `apikey` 路由表，进入编辑模式并添加规则。例如：

```json
{
  "enabled": true,
  "rules": [
    {
      "name": "demo-default",
      "cond": "req_path_prefix_in(\"/\", false)",
      "targets": [
        { "cluster_name": "demo-cluster", "model": "doubao-pro-32k", "weight": 100 }
      ],
      "fallbacks": []
    }
  ]
}
```

本地保存后点击「提交并生效」，未提交前不会影响线上流量。

### 步骤 7：验证配置生效

完成以上步骤后，可通过以下方式验证：

1. 触发 Conf Agent 拉取或等待其定时轮询，确认 BFE 已完成热加载；
2. 使用 curl 发送请求，验证流量是否按规则转发到目标集群：

```bash
curl -H "Authorization: <API Key>" \
  -H "Content-Type: application/json" \
  -d '{"model":"doubao-pro-32k","messages":[{"role":"user","content":"hello"}]}' \
  http://<bfe-address>:8080/v1/chat/completions
```

## 报表与用量分析

控制台内置数据报表模块，面向管理员提供运营数据的统一可视化视图：总览指标卡、时序折线图、维度排行、占比分布与日志明细，无需额外部署 Grafana。报表数据来自 `/open-api/v1/report/*` 接口，前提是已按「第十八章 安装部署」完成报表形态配置：轻量形态（`[Report].Backend = "mysql"` + log-reader `mod_log_mysql` 插件）或标准形态（`Backend = "doris"` / `clickhouse` / `starrocks` + Kafka 链路）。配置 `[Report]` 后控制台展示数据报表菜单；未配置时报表模块不装配，菜单不出现，接口返回 404。

### 页面结构

报表页面分为**全局过滤栏**与**页签区域**两部分：

- **全局过滤栏**：分两行。时间区提供快捷时间按钮（1 小时 / 6 小时 / 24 小时 / 7 天）、起止时间选择器与「最新」按钮；维度区提供目标模型、API Key、服务商、Host、流式、状态码 6 个通用过滤项，行尾是「拆分维度」下拉与「查询」「重置」按钮。
- **页签**：分为**总览**与**明细**两个页签，过滤条件在页签间共享、切换后保持。

时间区与维度区的关键行为：

- **快捷时间**：点击后把结束时间置为当前时刻、起始时间置为「当前时刻 − 跨度」，并立即查询；手动改动起止时间后快捷按钮取消高亮。
- **「最新」**：保持当前跨度不变，把窗口整体平移到当前时刻后重新查询。
- **「重置」**：清空 6 项通用过滤项并把「拆分维度」复位为「不分维度」，随即重新查询，但**不改变时间范围**与快捷按钮高亮（避免同一按钮两次结果不一致）；需要回到默认窗口请点快捷按钮。
- **目标模型**（`models`）过滤的是路由后的目标模型，取值来自各集群实际支持的模型（`llm_config.models`），不含仅作为请求别名出现的模型名；其余维度下拉的取值由当前时间窗口的排行接口动态填充。
- **「拆分维度」**：选项为不分维度 / 缓存状态 / 镜像命中 / 意图答案，**不是查询过滤条件**，只决定 QPS / Token / 延迟三张时序图是否按维度桶拆成多条序列，不影响指标卡、排行 / 占比 / 分布与明细表格；选中后需点「查询」才生效。

### 总览页签

总览页签展示选定时间窗口内的 **8 项指标卡**（请求总量、错误总量、Token 用量、平均延迟、费用、缓存命中率、镜像命中、意图分类）与 **7 张图表**（QPS 时序、Token 时间序列、延迟时间序列、排行、占比、分布、缓存 Token 时序）。时序数据的采样间隔由服务端按窗口自动计算，客户端无需传参；成本数据按币种分开展示，总览卡主值取首个币种（金额 + 币种小字），其余币种以副行列示，无成本数据时显示「-」。排行、占比、分布三张图的图卡标题旁各有维度下拉，切换后立即按新维度重新取数（不需要点「查询」）。

> 延迟分位数仅标准形态后端（Doris / ClickHouse / StarRocks）返回，界面固定只取平均值与最大值；MySQL 轻量形态无原生分位数。

### 明细页签

明细页签展示**服务端分页的日志表格**：

- 默认每页 **20** 条（可切换 20 / 30 / 40 / 50），按时间倒序排列（最新请求优先）；
- 固定 15 列：时间、API Key、请求模型、目标模型、服务商、状态码、耗时、Tokens、TTFT、费用、缓存、镜像、意图答案、错误、操作；
- 工具栏另有 8 个过滤项，仅影响日志表格查询：请求模型（`requested_models`）、仅错误（`err_only`）、关键词（错误详情模糊匹配，上限 128 字符）、缓存状态（`hit` / `miss` / `skip`）、镜像命中、意图问题、意图答案（含 `unknown`）、意图来源（`explicit_header` / `classifier` / `cache`）；
- 操作列「详情」打开右侧抽屉，展示 logid、日志时间、主机、产品线、API / 请求模型 / 目标模型 / 服务商、协议与模式、流式、状态码与错误码、错误信息、输入 / 输出 / 总 Token、耗时、TTFT、TPOT、费用、各级标签、客户端 IP 与 Host、原始 URI、缓存状态、镜像命中（含镜像集群）、意图问题 / 答案 / 置信度 / 来源 / 延迟 / 缓存命中 / 版本等字段，底部为 `ai_rate_limit_hits`、`ai_auth_reject_quota_plans`、`req_headers`、`res_headers` 四个可折叠 JSON 区。

### 接口层视图

报表页签背后的接口仍按以下五类视图组织，便于自动化与二次开发：

| 视图 | 内容 | 对应接口 |
|------|------|----------|
| 总览 | 请求总量、错误率、Token 合计、平均延迟、TTFT/TPOT、成本（按币种）、缓存命中率、镜像命中、意图分类 | `GET /report/overview` |
| 时序趋势 | QPS、Token 吞吐、延迟、TTFT/TPOT、成本增速、缓存 Token 的桶化曲线，时间桶随窗口自适应（≤6h 为 1 分钟桶），`dimension` 支持按 `ai_cache_status` / `mirror_hit` / `ai_intent_answer` 拆分 | `GET /report/timeseries` |
| 排行 | 模型、提供商、API Key、主机、状态码、协议、模式、缓存状态、镜像命中、意图答案等维度的 TopN 请求量排行 | `GET /report/rankings` |
| 分布 | 状态码、协议、模式、流式、缓存状态、镜像命中、意图答案的占比饼图 | `GET /report/distribution` |
| 日志明细 | 单条请求明细，支持请求模型、只看错误、错误关键字、缓存状态、镜像命中、意图问题 / 答案 / 来源过滤，按时间倒序分页 | `GET /report/logs` |

使用要点：

- **时间窗**：所有视图共用时间选择器，窗口最长 7 天（与明细保留期对齐），超过 7 天请在过滤栏分段查询：计数类指标可相加，平均值与占比类不能直接相加。
- **权限**：报表为管理员功能，需要 `FeatureReport + ActionReadAll` 权限；`system_admin` 与 `system_admin_readonly` 角色、`System` 与 `SystemReadonly` Scope 的 Token 均满足要求。
- **形态差异**：MySQL 轻量形态不提供 P50/P90/P99 分位数延迟，界面不展示分位数指标；标准形态展示完整分位数。如有分位数需求，建议使用标准形态后端。
- **口径一致**：报表指标与既有 Grafana Dashboard 面板同源，同一数据源下两套视图可对账。

## 操作日志与审计

操作日志模块（侧栏「操作日志」）提供平台写操作的**只读审计查询**。日志由系统在配置变更时自动写入，控制台不提供手工录入入口；系统管理员（含只读角色）均可访问。

### 列表页

页面分为**时间筛选栏**与**分页表格**两部分：

- **时间范围筛选**：设置起始时间、结束时间后点击「查询」，按闭区间过滤日志；未设置时间时展示全部（受分页限制）。
- **表格列**：操作人（模糊搜索，执行操作的控制台用户或 Token 名称）、操作动作（下拉筛选，`create` / `update` / `delete` / `reset` / `import` / `bind` / `unbind` 等，以 Tag 展示）、资源类型（下拉筛选，以中文标签展示）、资源名称（模糊搜索）、结果（成功 / 失败）、操作时间（格式 `YYYY-MM-DD HH:mm:ss`），操作列为「详情」按钮。
- **资源类型标签**：下拉与列均使用中文文案 —— Entity、Entity 类型、API Key、服务商、集群、路由、证书、配额计划、模型定价、批量任务（`batch`）、批量文件（`batch_file`）、用户、Token。
- **分页**：本模块采用服务端分页（默认每页 20 条，可切换页码与每页条数），与部分模块的前端分页不同。

### 详情抽屉

点击行操作「详情」，右侧滑出详情抽屉，展示操作者类型（用户 / Token）、操作人、操作动作、资源类型、资源 ID、资源名称、父级资源 ID、结果、错误信息（仅失败时展示）、变更摘要、请求路径与请求方式、客户端 IP、User-Agent、操作时间。其中**变更摘要**可展开查看 `before` / `after` JSON 对比与差异字段，敏感字段已脱敏。

### 日志来源与权限

以下写操作成功或失败后均会自动产生操作日志：Entity / Entity 类型、API-Key、模型服务商、业务集群、路由表、证书、配额计划、模型定价、控制台用户与 Token、批量任务（取消任务，`resource_type=batch`）。典型用法是在其他模块完成配置变更后，回到操作日志按资源名称或时间范围检索，核对变更内容与操作者。

无读权限时接口返回 `Feature Access Deny`（402），列表无法加载；若看不到「操作日志」菜单，请确认账号是否具备对应功能权限。

## 操作注意事项

在使用 Dashboard 进行日常运维时，应注意以下事项：

1. **默认账号安全**：`admin/admin` 仅用于首次登录，生产环境必须立即修改密码并限制访问来源；内置 `admin` 角色固定为「系统管理员」，不可变更。
2. **权限模型**：控制台用户分为 `system_admin`（系统管理员）与 `system_admin_readonly`（系统管理员（只读））两种角色，只读角色的导航与页面不做裁剪，写操作按钮隐藏，全部写接口返回 403，且 API-Key、服务商 Keys、Token 等敏感字段在界面与接口响应中脱敏；Token 分为 `System`（完整管理权限）、`SystemReadonly`（全部资源只读）与 `Support`（只读导出权限），为 Conf Agent 或自动化脚本创建 Token 时优先使用 `Support` Scope。
3. **密码与用户名约束**：密码 8–72 字节（UTF-8 字节计）、不能包含空格、不能与用户名相同或为其逆序；用户名最多 64 字符，保留名 `admin`、`root`、`system` 不可创建。
4. **Provider 变更的级联影响**：修改 Provider 的实例池、Keys 或模型列表会触发引用它的 Cluster 同步更新；删除 Provider 前必须确保无 Cluster 引用，否则将返回 `409 Conflict`。
5. **Cluster 删除的引用检查**：删除 Cluster 前，系统会检查其是否被 Global / Entity / API-Key 路由规则引用；若被引用，需先解除引用或修改规则。
6. **集合型配置的两步保存**：路由表、AI缓存规则、流量镜像规则、意图配置、AI上下文压缩都需「进入编辑模式 → 本地保存 → 提交并生效」。未提交的修改不影响线上流量，提交后才会生成新版本并触发 Conf Agent 拉取。
7. **配置生效延迟**：Dashboard 中的修改写入 MySQL 后，需经 Conf Agent 拉取并触发 BFE 热加载才能生效。不要期望配置保存后立即在数据面生效。
8. **版本号变化才代表真实变更**：即使多次点击保存，只要配置内容的 MD5 签名未变，`config_versions` 中的版本号就不会增加，数据面也不会重新加载。
9. **API-Key 明文脱敏展示**：API Key 列表中 Key 值脱敏显示（前 8 位 + `****` + 后 4 位），点击可查看完整值并复制；Key 值创建后不可修改，请创建成功后立即妥善保管。
10. **操作日志只读审计**：操作日志由系统在写操作时自动记录，仅支持查询，不提供修改与删除入口；如需核对历史变更，可按资源名称或时间范围在操作日志中检索。

## 本章小结

本章介绍了壬远 AI 网关 Dashboard 的基础操作。主要内容包括：

- Dashboard 默认通过 `http://api-server:8183/login` 访问，初始账号为 `admin/admin`；标题与图标可由部署目录下的 `branding/branding.json` 在部署后定制；
- 控制台导航为「左侧导航 + 右侧内容区」，覆盖资源管理（模型服务商、AI 业务集群、模型定价、EPP调度）、路由管理、功能增强、消费者管理（Entity 管理、批量任务、API Key 管理）、系统安全（密钥收敛）、数据报表、用户管理与操作日志；
- 模型服务商、AI 业务集群、模型定价、Entity 组织、API Key、路由表是控制台中的核心概念，理解它们的职责与引用关系是正确配置的前提；
- 控制台采用抽屉表单、列表页、视图 / 编辑双模式等通用交互；集合型配置需先本地保存再提交生效，编辑模式下可拖拽排序、顺序即优先级；
- 用户角色为 `system_admin` / `system_admin_readonly`，创建用户与变更角色均在界面上完成（内置 `admin` 角色固定）；只读角色的菜单与页面不裁剪，差异在写操作按钮隐藏与密钥脱敏；Token 分为 `System`、`SystemReadonly` 与 `Support` 三种 Scope；
- 批量任务页面以游标分页展示 provider 原生批量任务，提供筛选、详情抽屉与取消（终态不可取消），没有新建入口；
- 密钥收敛页面以三个卡片组织触发、运行中任务与历史任务，任务为集群级单例，运行中重复触发返回 409；
- 配置版本基于 MD5 签名与 `YYYYMMDDHHMMSS` 版本号实现增量同步，主要暴露给 InnerAPI 与 Conf Agent；
- 首次配置应按照“模型服务商 → AI 业务集群 → Entity（可选） → API Key → 路由规则 → curl 验证”的顺序进行；
- 数据报表模块提供总览（8 项指标卡 + 7 张图表）与明细（服务端分页日志表格）两个页签，支持快捷时间与「最新」平移窗口、「拆分维度」拆分时序图，配置 `[Report]` 并部署报表形态后方可使用；
- 操作日志对平台写操作进行只读审计，资源类型以中文标签展示，支持时间范围筛选与含变更摘要（before / after JSON，敏感字段脱敏）的详情抽屉；
- 日常运维需注意默认账号安全、级联引用检查、两步保存、配置生效延迟与 Token 最小权限原则。

掌握本章内容后，读者即可在 Dashboard 中完成壬远 AI 网关的初始化和基础管理操作，为后续章节中 Provider、Cluster、API-Key、限流等专项配置打下基础。
